# Verifying a release

`grintion-release-verify` checks a release artifact against a checksum file and,
when a public key is supplied, a detached Ed25519 signature over that checksum
file.

## Current status

Grintion-OS 0.9.x does **not** publish a release signing key. The verifier can
check the `.sha256` file, but without a published public key it can only prove
that the download matches the checksum file; it cannot prove who produced the
artifact. The tool prints an explicit warning in that case.

Do not describe a 0.9.x artifact as "signed" or "verified" just because the
checksum matches.

## Verify an artifact

```sh
grintion-release-verify output/grintion-os-x86_64.iso
grintion-release-verify output/grintion-os-x86_64.iso \
    --sha256-file output/SHA256SUMS \
    --key release-public.pem
```

Options:

| Option | Effect |
| --- | --- |
| `--sha256-file FILE` | Checksum file to read. Default: `<artifact>.sha256`. |
| `--signature FILE` | Detached signature over the checksum file. Default: `<sha256-file>.sig`. |
| `--key FILE` | Trusted Ed25519 public key (PEM). Required for signature verification. |
| `--require-signature` | Fail when no signature/key is supplied. |
| `--json` | Machine-readable result. |

The command exits 1 on a checksum mismatch, a missing checksum entry, a missing
signature when one was required, or a failed signature.

## Produce a signed checksum file

The private key is an offline release asset. It is not generated by this
repository and must not be committed.

```sh
GRINTION_RELEASE_KEY=/secure/offline/release-private.pem make sign-release
```

That writes:

```text
output/SHA256SUMS
output/SHA256SUMS.sig
```

Then publish the ISO, `SHA256SUMS`, `SHA256SUMS.sig`, the public key and
`BUILD-INFO` together. Verify before publishing:

```sh
grintion-release-verify output/grintion-os-x86_64.iso \
    --sha256-file output/SHA256SUMS \
    --key release-public.pem \
    --require-signature
```

## What each layer proves

| Layer | Proves | Does not prove |
| --- | --- | --- |
| SHA-256 | The bytes match the checksum file. | Who wrote the checksum file. |
| Detached signature | The checksum file was signed by the matching private key. | That the build itself is reproducible or audited. |
| `BUILD-INFO` | Which kernel/initramfs hashes and git commit were used. | That those inputs were not tampered with before signing. |

Reproducible builds and signed `BUILD-INFO` are Phase 7 work. Until then, a
signature authenticates the artifact that was signed, not the process that
produced it.
